# Lær for eksamen

Norwegian-first exam practice app for university courses: organise course material by **subject (emne)**, listen to it with local Norwegian TTS, and practise with **flashcards**, **quiz** and **active recall** generated by Claude.

The site is public to read and listen to. Only the admin (you) can upload pensum, make practice material and make audiobooks. Audiobooks are made on your own machine with Piper and published as MP3, so the hosted site never runs Piper.

| Who | Can |
| --- | --- |
| Anyone | Read documents, listen to published audiobooks with sentence following, practise flashcards, quiz and recall |
| Signed in with Google | The same, with progress (card reviews, recall scores, where you stopped listening) saved to the account |
| Admin (`ADMIN_EMAILS`) | Upload and delete pensum, edit subjects, make practice material with Claude, make and publish audiobooks |

Convex checks the admin role on every write, so hiding the buttons is not the only protection.

Documents are extracted in the browser (PDF.js / Mammoth). Text for read-aloud goes only to the **local** FastAPI + Piper TTS server. Text is sent to Claude (Anthropic) only when you click **Lag med Claude** to generate practice material.

## Practice modes

| Tab | What it does |
| --- | --- |
| Pensum | Upload PDF/DOCX/TXT or paste text into the active subject, pick a document, generate or import practice material |
| Lytt | Published audiobook with sentence following and chapters, continues where you stopped (keeps playing while you switch tabs). The admin also gets **Generer tale** and **Publiser lydbok** |
| Flashcards | Spaced repetition (Igjen / Vanskelig / Bra / Lett, keys 1–4, space to flip) |
| Quiz | Multiple choice with explanations, score and a retry of the ones you missed |
| Gjenkalling | Explain a topic in your own words, then tick off the key points you covered; weakest prompts come first |

Practice tabs work on the whole subject or one document. Subjects, documents, study sets and audiobooks live in **Convex**. Progress follows your Google account; signed out it stays in the browser's `localStorage` and moves to the account the first time you sign in.

## Audiobook workflow (admin)

1. Start the local backend (Piper) on your machine.
2. Open the site, sign in, pick a document and open **Lytt**.
3. Click **Generer tale**. Piper reads the document locally; you can listen to the local version while it works.
4. Click **Publiser lydbok**. The backend encodes the audio as MP3 (64 kbps, about a fifth of the WAV), it is uploaded to Convex storage, and the length of every chunk goes along so listeners can follow the text sentence by sentence.

To do this from the published site rather than `localhost:3000`, add its address to `backend/.env` and restart the backend: `CORS_ORIGINS=https://your-site.vercel.app`. Chrome asks once whether the site may reach devices on your local network; allow it.

## Practice material workflow

1. Upload pensum under **Pensum** and select the document.
2. Click **Lag med Claude**. The backend sends the document text to Claude and gets back flashcards, quiz questions and recall prompts (counts and an optional focus are adjustable).
3. Practise in the Flashcards / Quiz / Gjenkalling tabs.

Without an API key you can still **Importer JSON** in this format (and **Eksporter JSON** to back up or edit a set):

```json
{
  "summary": "…",
  "flashcards": [{ "front": "…", "back": "…", "section": "…" }],
  "quiz": [{ "question": "…", "options": ["…", "…", "…", "…"], "answer_index": 0, "explanation": "…", "section": "…" }],
  "recall": [{ "prompt": "…", "key_points": ["…"], "section": "…" }]
}
```

Add to `backend/.env` and restart the backend:

## Course files

The source material lives in `pensum/`, one folder per subject:

```
pensum/
  navneendringer.tsv      original file name → where the file is now
  okonomi/
    leksjon/              the lessons (DOCX/PDF), numbered as in the course
      lesetekst/          cleaned-up Markdown used by Les
    lydbok/               scripts written for listening, used by Lytt
    presentasjon/         lecture slides (PPTX/PDF)
    oving/                exercises, your submissions, tabellarisk-avslutning.html
      ovingssett/         practice sets (JSON for Importer JSON) and the text they were made from
  pmf/
    leksjon/
    oving/ovingssett/
```

What the app shows comes from Convex; these files are the originals you upload from.

## Architecture

```
frontend/          Next.js + TypeScript + Tailwind + shadcn/ui, hosted on Vercel
  └─ extract PDF/DOCX/TXT client-side
  └─ chapter detection + TTS chunking
  └─ audio player (play/pause/seek, resume, sentence following)
frontend/convex/   Convex: content, audiobook files, Google sign-in, per-user progress

backend/           FastAPI + Piper TTS (Norwegian Bokmål), only on the admin's machine
  └─ job queue with sequential chunk synthesis
  └─ retry failed chunks
  └─ merge WAV in order, encode MP3 for publishing
  └─ Claude for practice material
```

## Norwegian voice model

| Field | Value |
| --- | --- |
| Model | `no_NO-talesyntese-medium` |
| Engine | [Piper](https://github.com/OHF-Voice/piper1-gpl) (`piper-tts`) |
| Language | Norwegian Bokmål (`no_NO`, espeak `nb`) |
| Sample rate | 22 050 Hz |
| Voices repo license | MIT (`rhasspy/piper-voices`) |
| Training data | [NB Talebanken](https://www.nb.no/sprakbanken/en/resource-catalogue/oai-nb-no-sbr-15/) — **CC0** |
| Piper engine license | GPL-3.0-or-later |

Verified locally: the ONNX model loads and synthesizes Norwegian speech via the Python API.

### Required model files

Place these under `backend/models/` (or download with the command below):

- `no_NO-talesyntese-medium.onnx` (~63 MB)
- `no_NO-talesyntese-medium.onnx.json`

```bash
cd backend
source .venv/bin/activate
python -m piper.download_voices no_NO-talesyntese-medium --data-dir models
```

## Setup

### 1. Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m piper.download_voices no_NO-talesyntese-medium --data-dir models
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Health check: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)

### 2. Convex (dev)

```bash
cd frontend
npm install
npx convex dev
```

The first run asks you to log in and create a project, then writes `NEXT_PUBLIC_CONVEX_URL` to `frontend/.env.local`. Keep it running while you develop. Set the sign-in variables for the dev deployment (your Google address is the admin; several can be comma-separated):

```bash
node scripts/setup-auth.mjs http://localhost:3000 you@gmail.com
```

Then the Google client (see **Google sign-in** below):

```bash
npx convex env set AUTH_GOOGLE_ID <client id>
```

```bash
npx convex env set AUTH_GOOGLE_SECRET <client secret>
```

Move the library from the old local store (`backend/data/store`) once, before publishing audiobooks (it replaces subjects, documents and study sets):

```bash
node scripts/migrate-local.mjs
```

### 3. Frontend

```bash
cd frontend
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

Optional: set `NEXT_PUBLIC_TTS_API_URL` if the API is not on `http://127.0.0.1:8000`.

## Publishing on Vercel

1. **Convex production.** In the Convex dashboard, open the project's production deployment, go to Settings and create a deploy key.
2. **Vercel project.** Import the GitHub repo in Vercel and set **Root Directory** to `frontend`. `frontend/vercel.json` sets the build command to `npx convex deploy --cmd 'npm run build'`, which pushes the Convex functions and sets `NEXT_PUBLIC_CONVEX_URL` during the build. Add the environment variable `CONVEX_DEPLOY_KEY` (Production) with the deploy key, then deploy.
3. **Sign-in on production**, with the site's real address:

   ```bash
   node scripts/setup-auth.mjs https://your-site.vercel.app you@gmail.com --prod
   ```

   ```bash
   npx convex env set --prod AUTH_GOOGLE_ID <client id>
   ```

   ```bash
   npx convex env set --prod AUTH_GOOGLE_SECRET <client secret>
   ```

4. **Content on production:**

   ```bash
   node scripts/migrate-local.mjs --prod
   ```

### Google sign-in

In Google Cloud Console, open Google Auth Platform, set up the consent screen (External, then publish it so anyone can sign in), and create an OAuth client of type **Web application**:

- Authorized JavaScript origins: `http://localhost:3000` and `https://your-site.vercel.app`
- Authorized redirect URIs: the deployment's HTTP Actions URL (like the Convex URL, but ending in `.convex.site`) plus `/api/auth/callback/google`, for both the dev and the production deployment

## MVP features

1. Upload PDF, DOCX, TXT or paste text
2. Extract text with heading/chapter structure
3. Strip repeated headers/footers/page numbers (heuristic)
4. Generate Norwegian speech with Piper `talesyntese`
5. Playback: play, pause, seek, volume, 0.75x–2x
6. Long documents → sequential chunks, progress UI, retry failed chunks
7. Export WAV, publish MP3
8. Speech is made locally; only finished MP3s are published
9. Study UI with library + chapter navigation

## API (local)

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/health` | Voice readiness |
| POST | `/tts/jobs` | Create chunked synthesis job |
| GET | `/tts/jobs/{id}` | Progress |
| POST | `/tts/jobs/{id}/retry` | Re-queue failed chunks |
| GET | `/tts/jobs/{id}/audio` | Download merged WAV |
| GET | `/tts/jobs/{id}/audio.mp3` | The same audio as MP3, for publishing |
| GET | `/study/health` | Whether Claude is configured |
| POST | `/study/generate` | Generate flashcards, quiz and recall prompts for a document |
| GET | `/store` | The old local store, read by `scripts/migrate-local.mjs` |
| PUT | `/store/{key}` | Save one key in the old local store |

Chunks are capped at ~700 characters on the client and max 2000 characters per request body field on the server — never send an entire long document in one TTS call.

## Privacy

- Extraction runs in the browser.
- Piper and the FastAPI process run on your machine.
- Uploaded pensum and audiobooks are public on the site. Only upload material you are allowed to share.
- Document text is sent to Anthropic only when you generate practice material with Claude.
- Progress is stored per Google account in Convex; the site keeps your name and email from Google.
